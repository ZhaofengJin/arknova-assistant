# ArkNova 记牌与建议助手 — 规格

Status: ready-for-agent

## Problem Statement

我在 BGA(Board Game Arena)上玩方舟动物园时，难以凭记忆追踪哪些牌已经消耗、剩余牌库里还有什么、抽到关键牌的概率有多大；同时在回合决策时缺少一个参考视角来评估展示区和手牌里哪张牌更值得拿/打、下一步该优先做哪个行动。这些信息全部公开可见，但人脑记不住也算不快。

## Solution

一个安装在我浏览器里的油猴脚本：在 BGA 方舟动物园对局页面注入一个可折叠悬浮面板，自动读取游戏日志和页面 DOM，实时完成记牌(推算剩余牌库构成与概率)，并基于启发式规则给出卡牌评分和五大行动的优先级建议。仅作个人学习参考，不上架、不宣传，在友谊赛/练习局使用。

## User Stories

1. 作为一名方舟动物园玩家，我希望面板实时显示剩余牌库的完整清单，以便我知道牌库里还剩什么牌。
2. 作为一名玩家，我希望看到每张关键牌(我还没见到的牌)被抽到的概率，以便评估等待某张牌是否值得。
3. 作为一名玩家，我希望消耗牌(已打出、弃牌堆、展示区)被自动逐张追踪，以便我不需要手动记牌。
4. 作为一名玩家，我希望中途打开或刷新页面时记牌状态能从游戏日志完整重建，以便我不会因刷新丢失记牌。
5. 作为一名玩家，我希望展示区的每张牌有启发式评分和排序，以便我决定拿哪张。
6. 作为一名玩家，我希望手牌里的每张牌有评分和理由，以便我决定打哪张。
7. 作为一名玩家，我希望评分权重可以在面板上调整并保存，以便我通过调校理解各因素的影响。
8. 作为一名玩家，我希望看到五大行动(卡牌/建造/动物/赞助/协会)的优先级排序和一句理由，以便决策下一步行动。
9. 作为一名玩家，我希望建议基于完整公开局面(金钱、地图、协会板、合作动物园/大学、终局计分卡)，以便建议是“懂局势”的而非孤立评分。
10. 作为一名玩家，我希望面板可以折叠、拖动、收起，以便它不遮挡对局操作。
11. 作为一名玩家，我希望界面是中文、卡牌显示中文名+英文原名，以便对照 BGA 页面。
12. 作为一名玩家，我希望显示语言可配置切换，以便以后想用英文界面。
13. 作为一名玩家，我希望脚本通过 GitHub 仓库自动更新，以便我不用手动重装。
14. 作为项目的维护者(未来的我)，我希望卡牌数据(基础版+海洋世界扩展)是独立的结构化 JSON，以便未来加扩展不改代码。
15. 作为维护者，我希望核心逻辑是纯函数且有真实日志回放测试，以便 BGA 改版后我能快速定位和修复。
16. 作为维护者，我希望读取层(日志解析/DOM 抓取)足够薄且有快照测试，以便 BGA 前端改版时只需修这一层。

## Implementation Decisions

- **载体**:userscript(油猴脚本)，TS + Vite + vite-plugin-monkey 工程化构建，产物单文件 `.user.js`;不做浏览器扩展(见 ADR 0001)。
- **分发与更新**:构建产物挂 GitHub 仓库，利用 userscript 的 `@updateURL`/`@downloadURL` 自动更新；仓库不宣传。
- **模块划分**(单向数据流):
  - 读取层:游戏日志解析为主通道，DOM 抓取校验兜底;输出规范化的事件流与局面快照。中途加载时从日志开头回放重建状态。
  - 记牌核心(纯函数):输入卡牌池 + 消耗牌事件流，输出剩余牌库与每张未现牌的概率。
  - 评分引擎(纯函数):输入局面状态 + 权重配置，输出展示区/手牌各卡评分与排序。
  - 建议引擎(纯函数):输入完整公开局面，输出五大行动优先级排序 + 一句理由。
  - 面板 UI:可折叠悬浮面板，注入对局页面;权重可在面板调整并持久化(localStorage)。
  - 卡牌数据库:独立 JSON(基础版 + 海洋世界扩展),以社区开源数据为底、人工校对;卡牌的稳定 key 用英文原名。
- **语言模式**:界面中文;卡牌显示中文名 + 英文原名;显示语言可配置;匹配逻辑只依赖英文原名 key。
- **概率模型**:未知池 = 卡牌池 − 消耗牌 − 我的手牌(手牌对我已知);未知牌分布在真实牌库与对手手牌中，按均匀隐含分布计算概率。跨越已知/未知边界的事件(如偷窃:我偷别人=未知变已知，别人偷我=已知变未知)必须即时更新推算;对手之间的偷窃(未知→未知)不影响推算。
- **持久化**:仅权重配置、面板位置/折叠状态、语言模式存 localStorage;对局状态不持久化(每局从日志重建)。

## Testing Decisions

- 只测外部行为，不测实现细节。
- **主接缝(唯一新接缝)**:「事件流 → 局面状态 → 评分/建议」纯函数管线。用真实对局日志做回放 fixture，断言任意时刻的剩余牌库、概率、评分排序与建议输出。
- **读取层**:用保存的真实网页快照(DOM)+ 日志文本做解析测试;这是抗 BGA 改款的保险丝。
- **面板 UI**:不做自动化测试，手动目检。
- 项目为全新代码库，无既有测试先例;测试框架随 Vite 技术栈(Vitest)。

## Out of Scope

- 完整 solver / 穷举搜索引擎(明确不做)。
- v1 不做对局记录与赛后复盘(代码留 hook,v2 再议)。
- 浏览器扩展形态、Chrome 商店上架、Firefox 适配。
- 海洋世界之后的其他扩展。
- 多人协作、云端同步、任何形式的遥测或数据上传。

## Further Notes

- 合规边界:仅聚合公开可见信息 + 启发式建议，定位个人学习参考;BGA 生态有同类记牌插件先例(Azul 记牌器等)，但实时建议在竞技场合有争议，使用者自行把握场合。
- **开工前置条件**:需要一份真实对局的完整网页保存(网页，全部)+ 游戏日志文本，用于逆向日志格式与 DOM 结构(M0 的输入)。
- 卡牌数据来源:GitHub 社区开源 ArkNova 卡牌数据集为底，人工对照牌表校对补齐 Marine Worlds;仅供个人使用，不二次分发。
- **语言匹配(2026-10-08 修正)**:用户 BGA 为中文界面,日志与 DOM 中的卡名是中文(且行动卡名中英混杂,如"Build、卡牌 1"),"只依赖英文原名匹配"的假设不成立。内部仍以英文名做 key,但解析层必须把中文显示名映射到 key;更优路径是验证 BGA 卡牌元素是否带官方数字编号,若有则按编号匹配,彻底绕开语言问题(待 DOM 样本验证)。
- 术语以根目录 `GLOSSARY.md` 为准;架构决策见 `docs/adr/0001-userscript-over-browser-extension.md`。

## 用户典型对局配置

来自用户 2026-10-08 提供的 BGA 建房偏好，是读取层与卡牌数据库必须兼容的目标环境:

- 3 人局，快速回合，高级模式(非和平模式:存在“毒液”“偷窃”等互动牌)
- 扩展:海洋世界(仅基础游戏的情况可选，但用户常开扩展)
- 动物园地图包 2:启用(额外地图 11、12、13、14、T1);地图包 1 被发布者禁用
- 替代地图:启用(地图 1-8 有轻微变化);玩家地图为所有玩家相同的随机地图

## Milestones

- **M0 可行性原型**:读懂真实日志与 DOM，能重建一局的状态时间线。
- **M1 记牌器**:剩余牌库清单 + 关键牌概率，面板展示。
- **M2 启发式评分**:展示区/手牌评分排序，权重可调。
- **M3 局面建议**:五大行动优先级 + 理由。
